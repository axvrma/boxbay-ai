# Domain and persistence model

A facility revision contains rack dimensions, service areas, crane settings, slot restrictions, operating weights and the grid conversion factor. Slot keys are `rack:bay:level:position` using one-based indices. Coordinates are meters. Every rack has one crane and each crane is confined to its rack. Tray routes link a shared transverse spine to handoff points below the bays. Each crane has a load cap, speed, hoist, equipment mass and energy parameters.

A scenario snapshot contains the full facility revision, seed, offset-aware start timestamp, initial inventory, workload and intervention schedule. Container records include length, weight, carrier, optional vessel, hazard, appointment, hold and priority. Work adds boundary release, pickup request, initial slot and optional cutoff. Durations and deadlines are relative seconds. A run stores snapshot, model and dataset versions, trace, dispatch evidence and metrics. A benchmark stores matched seed rows and summaries.

Migration 001 establishes an append-only document store keyed by kind, identifier and revision. Existing scenario and run documents retain their embedded topology. A topology edit from the default browser editor creates a fresh seeded scenario. Applying a topology to a saved inventory checks slot references and compatibility before running.

Stored runs preserve their original traces. Restoring a pre-tray scenario maps legacy primary crane assignments to dedicated racks. A rack without a historical owner receives an offline crane. Tray timings are generated by the new run.
